T1 · 编辑器事务与快照：人工跑测指南

版本：2026-09-19 · 目标：低成本验证 T1，不启动全量渲染回归，不开多个命令行窗口。

先看结论： T1 的核心验收是“事务、快照、回滚、JSONL replay”的定向测试，不是截图测试。 当前启动器的 Inspector 仍使用旧的编辑命令路径，所以 UI 冒烟只能证明编辑器还能启动、编辑、撤销、保存，不能单独证明新 EditorHistory API 已经接入 UI。

0. 测试范围

项目本次是否覆盖说明
Apply / Undo / Redo 失败回滚是包括文件保存失败时 world 与 history 不被破坏。
Snapshot schema v2是白名单组件序列化，并排除运行时 Entity bits。
Copy / Delete / Rename / AddComponent是通过稳定名称和 JSONL 操作重放验证。
Metal / 光照 / 阴影 / SSAO / SSR 截图否T1 不改渲染管线；不要为 T1 跑全量截图矩阵。
启动器 Inspector UI人工冒烟验证当前 UI 可启动、编辑、撤销、保存、重开。

1. 推荐跑法：一次命令完成 T1 定向验收

只需要一个终端窗口，在项目根目录执行：

cd /Users/ruochenhua/AetherEngine
./scripts/verify-editor-t1.sh 20260919-t1-manual

预期输出：

T1 report: tests/reports/20260919-t1-manual.html

然后打开报告：

open /Users/ruochenhua/AetherEngine/tests/reports/20260919-t1-manual.html

报告中的三个 primary case 都应为 PASS：

Case验证内容通过标准
t1_editor_transaction保存失败、Undo/Redo 保存失败时的原子回滚测试进程退出码为 0；报告显示 PASS。
t1_snapshot_whitelistschema v2 快照与运行时字段隔离快照只包含白名单组件，不包含 Entity bits。
t1_editor_command_replay命令序列、Undo/Redo、JSONL replay 的确定性replay 后 state hash 与原状态一致。

2. 想看完整 Rust 测试输出时

仍然在同一个终端执行：

cargo test -p aether-engine editor::tests -- --nocapture

当前应有 7 个 editor 测试通过。若某个测试失败，先保留终端输出和上一步生成的 HTML，不要立即重跑全量 CI。

3. 人工启动器冒烟（可选）

这一节验证当前编辑器 UI 的基本可用性。它不是 T1 核心事务 API 的完整 UI 验收。

  1. 构建一次 release launcher（如果最近已经构建过，可跳过）：
    cargo build --workspace --release
  2. 用一个终端启动编辑器，建议先使用编辑器综合场景：
    target/release/aether-launcher --scene scenes/15_editor_terrain_water.ron
  3. 在层级面板选择一个对象，修改 Transform 或材质参数，确认画面和 Inspector 会更新。
  4. 按 Cmd+Z（Windows/Linux 使用 Ctrl+Z），确认修改撤销；再按 Cmd+Y/Ctrl+Y，确认修改恢复。
  5. 使用 File → Save Scene 保存到一个临时路径，例如 /tmp/aether-t1-manual.ron；关闭后用该文件重新打开，确认修改仍在。
  6. 结束时只关闭这一个 launcher 窗口；终端回到 shell 后，用下面命令确认没有残留进程：
    pgrep -fl 'aether-launcher|cargo test|verify-editor-t1' || true
如果启动器没有到第一帧： 不要连续开多个窗口，也不要继续启动全量场景。记录终端最后 30～50 行，关闭窗口或在同一终端按 Ctrl+C，再把输出和场景名发回来。这属于 launcher/runtime 启动问题，不要归因给 T1 事务逻辑。

4. 可选截图冒烟

T1 本身不要求截图对比；如果你想顺手确认启动器能自动退出并生成一张截图，只跑一个场景：

target/release/aether-launcher \
  --scene scenes/15_editor_terrain_water.ron \
  --screenshot /tmp/aether-t1-manual.png \
  --exit-after-frames 60 \
  --no-gui-overlay \
  --freeze-time

通过标准：进程自行退出、/tmp/aether-t1-manual.png 存在且能打开。截图只作为启动器冒烟证据，不更新任何视觉 reference。

6. 失败时只需要反馈什么

  • 失败的命令。
  • HTML 报告路径，或终端最后 30～50 行。
  • 如果是启动器问题：使用的场景名、是否显示窗口、是否到达第一帧。
  • 如果是截图问题：PNG 的绝对路径和打开后的现象。
本指南只针对 T1。渲染管线、SSAO、SSR、阴影等后续任务应各自建立专门场景、专门截图和专门回归记录。
