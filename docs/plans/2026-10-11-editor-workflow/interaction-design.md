# EW3–EW6 交互设计与评审合同

状态：交互基线草案；EW5-A 只读引用预览已实现 · 2026-10-17
适用阶段：EW3 资源拖放、EW4 导入、EW5 文件操作、EW6 资源预览分页

本文件先固定交互设计的工作方式和推荐基线。实现前仍需按阶段做可操作原型，解决具体布局和反馈问题，并由用户确认该阶段的操作合同。此处的推荐是 Aether 的设计决定建议，不代表参考引擎必然采用完全相同的实现。

## 设计评审流程

每个 EW3–EW6 切片按以下顺序推进：

1. **明确用户任务和当前状态。** 列出起点、目标对象、用户动作、现有选择、磁盘/场景状态，以及操作成功后的可见结果。
2. **并行进行多视角审阅。** 至少三项独立审阅：一项查两个或以上成熟引擎的官方交互资料；一项检查 Aether 当前架构、状态与输入路由；一项专门找取消、失败、Undo/Redo 和误操作风险。审阅者交付证据与建议，不直接改实现。
3. **综合成一个交互合同。** 官方资料事实与 Aether 推断分开。对每条流程写明入口、操作步骤、拖动/等待时反馈、提交点、取消与失败结果、Undo/Redo、选择和键盘焦点行为。
4. **先做低成本原型。** 对拖放、导入确认、引用影响确认和分页生命周期等交互，使用 HTML/截图或 egui 测试 UI 展示关键状态。原型覆盖正常路径、取消和至少一种失败路径。
5. **评审并确认合同。** 交付原型和简短流程表，请用户确认具体交互。未确认的行为不扩展成生产功能；可独立推进的研究和测试设计继续进行。
6. **按 TDD 实施。** 将确认后的操作写成可观察的行为测试，先 RED 后 GREEN；实现后按相同流程做真实 UI/运行验证，并更新计划与截图证据。

## Aether 推荐交互基线

### EW3 · 资源拖放

- Project 单击资源：只更新资源选择和详情预览，不改变 Scene entity selection。按住并超过拖动阈值才开始拖放，避免点击预览误触发。
- 拖动时显示资源名称/类型；只有兼容目标高亮，并显示将执行的动作。模型拖到视口显示放置反馈；MaterialAsset 与纹理只高亮可接受的准确属性槽。
- 仅在兼容目标上松开才提交。Esc、拖到无效位置、松到窗口外或资源类型不符均不修改场景、资源引用、选择状态或 Undo 历史，并给出简短原因。
- 已链接的 MaterialAsset 保持只读。赋 inline 纹理前要求用户显式执行 Detach；拖放本身不能隐式断开链接。一次成功赋值/实体创建对应一个 Undo/Redo 操作。
- 场景资源双击打开场景；其他资源在 EW6 前仍使用当前详情区预览。EW6 上线后，双击资源打开或聚焦对应预览页签。

### EW4 · 导入与新建文件夹

- 导入入口始终显示目标目录；默认目标是 Project 当前选中的允许目录。系统文件选择器提供第一版可靠入口，外部文件拖入 Project 可作为采用同一验证流程的快捷入口。
- 确认发布前展示文件名、识别类型、目标目录、依赖/缺失依赖和验证结果。批量导入可逐项显示成功或失败；取消和失败不留下半成品。
- 创建文件夹从工具栏或目录上下文菜单发起，直接进入名称编辑；Enter 提交，Escape 取消。非法名称或重名在原位置说明原因并保留可编辑状态。
- 导入成功后刷新并选中/定位新资源，提供行内完成反馈；详细诊断同时进入 Log。导入进度、完成、失败不能只靠日志表达。

### EW5 · 移动、重命名与删除

- **EW5-A 已交付：**“显示引用”只读预览固定分析目标，分别显示 Used by / Depends on，行内呈现精确来源、字段和解析状态。扫描不完整或有损坏/未知引用文档时明确显示“分析不完整”，不允许把“没有发现”解释成“未被引用”；引用行只导航 Project，不改变场景实体选择。
- 目前缺少通用脏场景标记，运行时 World、AssetManager 和 watcher 也仍保留路径键；在保存状态和 live-path 更新合同落地前，Move/Rename/Delete 保持禁用。
- F2 当前用于调试叠层；未来的重命名快捷键必须限定在 Project 资源行拥有焦点时，并在全局调试快捷键之前被 Project 消费。
- 重命名使用 F2 或上下文菜单，名称原位编辑；Enter 提交，Escape 取消。路径碰撞、非法名称或无法解析引用时，保留原资源并显示原因。
- 资源拖到目标目录时高亮目录；释放后先展示来源、目标路径及将更新的引用，再由用户确认提交。重命名使用同样的影响预览。
- 删除使用 Delete 或上下文菜单打开引用感知确认；列出资源和已知引用者，支持跳到引用位置。发现引用未覆盖、脏场景未保存或依赖文档损坏时阻止删除并给出下一步，不提供默认的强制删除绕过。
- 确认后的改写采用原子事务；取消或失败无副作用。成功后索引立即更新，并提供可行时的 Undo/Redo。Undo 不安全时必须明确说明原因，不伪装成可撤销。

### EW6 · 多资源预览分页

- EW6 指 Project 详情区域里的资源文档页签，与底部 Project/Log 工作区页签分开。首期只在主窗口内打开，不承诺独立原生窗口。
- 单击继续选择并更新当前详情；双击或上下文菜单的“在新页签打开”打开预览。重复打开同一资源时聚焦已存在页签，避免重复加载。
- 点击页签切换；页签有明确关闭按钮，关闭不删除资源、不改变 Scene entity selection。可在后续原型验证中键盘关闭和页签排序，不作为首期必要条件。
- 页签保留资源对应关系，不重复读取/上传相同资源。EW5 移动或重命名后由操作映射更新关联；外部删除或无法重新定位时保留失效页签，并提供定位 Project 项或关闭的操作。
- Project 目录、搜索、过滤与预览页签是独立状态；切换其中一项不清空其他状态。预览页签拿到键盘焦点时才处理自身快捷键，避免抢占场景快捷键。

## 跨阶段反馈规则

- 用户操作结果靠近操作位置反馈：有效目标高亮、行内状态或短暂提示；Log 用于完整诊断与后续定位，不作为唯一反馈。
- 无效操作说明具体原因和可行的下一步；取消是正常结果，不显示成错误，也不留下部分状态。
- 改变场景或项目文件的操作必须明确提交时点，并定义失败回滚和 Undo/Redo 范围；纯浏览/预览不隐式改写项目。

## 官方参考与 Aether 适配

以下是审阅中确认的官方交互依据；表内“适配”属于 Aether 的设计推断。

| 官方资料中的模式 | Aether 适配建议 |
|---|---|
| [Unreal 放置 Actor](https://dev.epicgames.com/documentation/en-us/unreal-engine/placing-actors-in-unreal-engine)：从 Content Browser 拖资源到关卡视口创建对应对象。 | 视口与具体属性槽都采用“目标高亮 → 松开提交”；无效目标保持无副作用。 |
| [Godot Inspector Dock](https://docs.godotengine.org/en/stable/tutorials/editor/inspector_dock.html)：拖动时兼容属性高亮，资源放到属性值上完成赋值。 | 纹理只高亮兼容槽；linked MaterialAsset 在赋值前要求显式 detach。 |
| [Unreal Working with Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/working-with-assets-in-unreal-engine)：移动/复制松手后呈现目标操作选项，删除会确认并检查引用。 | 展示将改变的路径和引用；未知引用或脏场景时阻止破坏性操作。 |
| [Godot Import Process](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/import_process.html)：支持的资源可拖入 FileSystem dock，并由编辑器导入。 | 同时提供明确 Import 入口；所有入口共用预检、依赖摘要、原子发布和失败反馈。 |
| [Blender Outliner Editing](https://docs.blender.org/manual/en/dev/editors/outliner/editing.html)：Outliner 提供 F2 重命名、Delete、Remap Users 和 Select Linked。 | 在实施资源改名或删除前先展示引用者与依赖边；首个 EW5 切片先只读列出引用，随后再开放安全写操作。 |
| [Unreal Content Browser](https://dev.epicgames.com/documentation/en-us/unreal-engine/content-browser-in-unreal-engine)：Content Browser 可多实例使用并可停靠或浮动。 | Aether 先做 EW6 主窗口页签；独立原生窗口留待渲染与事件路由专项设计。 |
| [Godot Script Editor](https://docs.godotengine.org/en/stable/tutorials/editor/script_editor.html)：脚本编辑器支持多个文件页签及关闭/切换操作。 | 多资源预览页签采用可预测的打开、复用、切换、关闭与失效状态合同。 |

这些来源记录的是其各自编辑器的具体功能。页签默认策略、Aether 的失败语义、Undo 范围及确认步骤为本计划提出的建议，需通过本项目原型和用户评审最终确定。
