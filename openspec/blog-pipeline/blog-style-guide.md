# AetherEngine 博客文章风格指南

> 基于用户历史文章（KongEngine 时期）分析得出的风格规范，用于指导 AI 生成博客内容。

## 1. 整体风格

- **语气**：第一人称，像资深工程师在分享经验，亲切但有技术深度
- **结构**：问题导向 → 原理讲解 → 代码实现 → 效果展示 → 总结
- **语言**：中文为主，技术术语保留英文（如 G-Buffer、PBR、Shadow Map）
- **篇幅**：中长篇，通常 2000-5000 字，代码片段丰富

## 2. 文章开头（引言）

**模式 A - 问题驱动**：
```
想要在Kong引擎里面实现的场景慢慢复杂了起来，光源和模型的数量...
是时候接入延迟渲染的方法了。
```

**模式 B - 背景介绍**：
```
好久不见，最近正处于工作比较忙的阶段...
今天这篇文章，算是对之前水面渲染的一个小小的延伸，也是填了之前埋得一个小小的坑。
```

**模式 C - 系列开篇**：
```
在2022年12月，我受邀在OGEEK上做过一次关于数字人渲染技术的分享...
由于PPT内容还是比较多的...于是乎会准备做成一个系列
```

## 3. 正文结构

### 3.1 原理讲解
- 用通俗语言解释技术概念
- 配合外部参考图（LearnOpenGL 等）
- 关键概念用 **粗体** 标注
- 适当使用 HTML 图片标签（WordPress 迁移遗留）

### 3.2 代码片段
- 语言：C++（KongEngine 时期）/ Rust（AetherEngine 时期）
- 风格：完整函数或关键逻辑块，带中文注释
- 注释位置：行尾或独立行，解释"为什么"而非"做什么"

```c++
// 顶点的世界坐标在projection和view matrix的转换下的坐标范围是[-1,1]
// 那么将在[-1,1]这个边界的八个顶点坐标乘以projection和view matrix的逆矩阵则可以得到视锥体边界的顶点的世界坐标
vector<vec4> frustum_corners;
```

### 3.3 数学公式
- 使用 MathML 或图片展示
- 从简单公式逐步推导到复杂公式

### 3.4 图片使用
- 示意图：引用 LearnOpenGL 等权威来源
- 效果截图：展示最终实现效果
- 动图：用于展示动态效果（如波形）

## 4. 结尾风格

- 总结实现过程中的关键决策
- 提及遇到的挑战（轻描淡写但真实）
- 预告下一步计划或系列下一篇
- 偶尔加入个人感悟（如工作忙碌、生活变化）

## 5. Front-matter 规范

```yaml
---
title: <技术名称>实现
date: YYYY-MM-DD HH:MM:SS
categories: 
  - 技术漫谈
tags: [3D, render, 渲染, 编程]  # 根据内容调整，如加水、数字孪生等
index_img: /YYYY/MM/DD/<slug>/banner.png
banner_img: /YYYY/MM/DD/<slug>/banner.png
---
```

## 6. 与 KongEngine 文章的差异

| 方面 | KongEngine | AetherEngine |
|------|-----------|-------------|
| 语言 | C++ / OpenGL | Rust / wgpu |
| 架构 | 传统 OOP | ECS + RenderGraph |
| 着色器 | GLSL | WGSL |
| 风格延续 | 技术深度、问题导向 | 保持，增加 Rust 特性讲解 |

## 7. 生成提示

生成文章时应：
1. 从 proposal 的 Why 出发，写出"为什么需要这个功能"
2. 参考 design.md 的 Decisions，解释关键设计选择
3. 从 tasks.md 提取实现步骤，转化为通俗的技术讲解
4. 代码片段使用 Rust + wgpu API，带中文注释
5. 结尾提及与 KongEngine 的对比或演进关系
