# AetherEngine → 博客自动化流水线 设计文档

## 1. 目标

当 AetherEngine 通过 OpenSpec 完成一个里程碑（Change Archive）后，自动生成对应的技术博客文章草稿，经用户审核后发布到 ruochenhua.github.io。

## 2. 触发条件

- OpenSpec workflow 进入 `archive` 阶段
- 检测到新的 archive 目录（如 `openspec/changes/archive/YYYY-MM-DD-<change-name>/`）
- 该 archive 包含完整的 `proposal.md` + `design.md` + `tasks.md`

## 3. 流水线流程

```
[Trigger] OpenSpec Archive 完成
    │
    ▼
[Extract] 读取 archive 中的 proposal/design/tasks
    │
    ▼
[Generate] 生成博客草稿（Hexo Markdown + front-matter）
    │
    ▼
[Review] 用户审核（clarify）→ 确认 / 修改 / 取消
    │
    ▼
[Publish] 写入 blog_source/source/_posts/
          hexo generate
          git commit & push
          hexo deploy
```

## 4. 博客文章结构

参考 KongEngine 历史文章风格（如 `defer-render.md`）：

```markdown
---
title: <功能名称>
date: <auto-generated>
categories:
  - 技术漫谈
tags: [3D, render, Rust, wgpu, 编程]
index_img: /YYYY/MM/DD/<slug>/banner.png
banner_img: /YYYY/MM/DD/<slug>/banner.png
---

## 引言
简述这个功能是什么，为什么要做

## 原理
技术原理讲解（配合示意图）

## 实现
核心代码片段 + 解释

## 效果
运行截图/录屏

## 总结
遇到的问题、后续优化方向
```

## 5. 与 OpenSpec 的集成点

| OpenSpec 产物 | 博客文章素材 |
|--------------|-------------|
| proposal.md | 引言、目标 |
| design.md | 原理、架构图 |
| tasks.md | 实现步骤 |
| 代码变更 | 核心代码片段 |
| 示例程序 | 效果截图/录屏 |

## 6. 审核机制

- 生成草稿后，通过 `clarify` 工具向用户展示：
  - 文章标题
  - 摘要（3 句话）
  - 目录结构
  - 预估阅读时长
- 用户选项：
  1. 直接发布
  2. 修改后发布（提供修改意见）
  3. 暂存为草稿（不发布，保存到 blog_source/source/_drafts/）
  4. 取消
